# 烹饪 AI 过程评价系统 · 项目使用说明书

| 项 | 内容 |
| --- | --- |
| 手册版本 | v1.0（对应前端 v1.2 / 2026-11-22） |
| 读者 | 教师、学生、系统管理员、验收与演示人员 |
| 前置知识 | 会用浏览器即可；不需了解技术细节 |
| 配套文档 | `docs/项目开发方案.md`（为什么这么设计）、`docs/后台开发说明书.md`（开发者用）、`docs/项目使用说明书.md`（本文件） |

> **一句话理解这个系统**：它把一节课拆成五个环节，每个环节的分数都能点开看到「哪台设备、哪一刻、
> 哪张抓拍」，教师确认或改完之后归档。AI 给的是**建议分**，最终成绩由教师定。

- 数据是固定的示例，**改动会在刷新后按演示数据规则重来**（公告这类数据会记住，成绩类不会）；
- 所有人脸识别结果都是模拟的，不会真的调用模型；
- 这是为了让演示不依赖服务器，**不是故障**。

## 3. 学生手册

### 3.1 我的一天（推荐顺序）

```
登录 → 工作台看今天上什么课 → 读菜谱（我的课程）→ 刷脸签到
     → 按提示完成各环节 → 看「我的成绩」→ 有疑问问智能 AI 老师
```

### 3.2 工作台 `/dashboard`

| 区域 | 内容 |
| --- | --- |
| 顶部四张卡 | 今日签到、上一节实训得分、本节已完成环节、待完成事项 |
| 本节课 | 课程名、实训目标、本节课的菜、实训时间、当前环节、签到状态 |
| 我的环节得分 | 五个环节的得分与权重；进行中的环节标「进行中」 |
| 已归档的成绩 | 历史成绩（归档后冻结，不会因调权重变化） |
| 右栏 公告 | 未读公告（点开阅读） |
| 右栏 待完成 | 阅菜谱、上传成品照、完成课堂问答 |
| 右栏 最近记录 | 签到、环节评价、教师扣分等动态 |
| 右栏 快捷入口 | 直接进签到、成绩、档案等 |

**看到「—」是什么意思**：该环节还没生成分数（未进行或未识别），不是 0 分。

### 3.3 人脸签到 `/face-checkin`

1. 点「打开摄像头」，浏览器会请求摄像头权限，选「允许」。
2. 把脸放进取景框的虚线圆角框内，保持正面、光线均匀。
3. 系统每 1.5 秒比对一次。成功会闪一下并提示姓名与相似度；失败会给具体原因
   （未注册 / 光线太暗 / 已签到过）。
4. 签到成功后点「继续识别下一位」（多人共用一台设备时）。

> **注意**：这个页面你**只能看到自己的签到记录**，看不到同班同学。
> 教师和管理员才能看全员记录——这是隐私边界，不是权限故障。

**签不上怎么办**：确认已录入人脸（个人中心有「已录入人脸」标识）；都没有就找教师人工补签。

### 3.4 我的课程 `/courses`

列表里只有教师**已发布**的课程。点进详情能看结构化菜谱（配料表 + 带关键控制点的步骤）。
点「解析这份菜谱」，系统会把难点与易错点标注到对应步骤上——**先看难点再动手**，能少返工。

### 3.5 五个评价模块（你只看到自己的）

| 页面 | 你要做什么 | 会得到什么 |
| --- | --- | --- |
| 着装规范 | 对着摄像头站好（帽子、上衣、围裙、袖口、发网） | 五项判定 + 不合格项提示 |
| 食材预处理 | 正常切配，镜头对准案板 | 切配频率、均匀度、关键帧 |
| 烹饪过程 | 正常操作，注意播报提示 | 六步时序、异常事件（跳步/离岗） |
| 菜肴成品 | 上传成品照片 | 五维（色泽、摆盘、刀工、火候、卫生）+ 建议分 |
| 综合评价 | 无需操作，查看即可 | 五环节加权总分、等级、教师评语 |

> 成品评分页底部有免责说明：**照片不能判断口味、内部熟度与食品安全**。这行字不能删。

### 3.6 我的成绩与档案

- 「我的成绩」（综合评价页）：本次实训的加权总分与等级、各环节得分、教师评语。
  点环节行能看到每条原始记录，**这是你申诉的依据**。
- 「我的实训档案」：历年实训趋势（折线图）、各环节问题、教师评语。可按学期/课程/类型筛选。
- 导出：成绩页面右上「导出我的成绩」下载 CSV（Excel 打开），「导出我的报告」打开 A4 打印页
  （浏览器里 Ctrl+P 另存为 PDF）。

### 3.7 智能 AI 老师 `/chat`

- 三种加附件方式：拖拽、粘贴、点回形针（图片与 PDF，单个 ≤20MB，一次 ≤4 个）。
- 适合问：这道菜的工艺要点、我这个环节为什么被扣分、某个步骤的标准是什么。
- **不适合问**：「我多少分」这类识别数值问题——它不知道你的实时分数，会把问题转回成绩页。
- 会话可保存，左侧抽屉里能翻历史。

### 3.8 个人中心 `/profile`

学生看到：学号、班级、人脸照片（含「已录入/未录入」标识）、手机号、邮箱、开通时间、上次登录；
右侧是「我的成绩」（本次加权分 + 环节条 + 近 6 次趋势）。

- 手机号与邮箱可自助修改（右上「修改联系方式」）。
- 学号、班级、姓名由教务同步，个人改不了；有错请找管理员。
- 人脸照片只用于本人签到比对，可申请注销。

## 4. 教师手册

### 4.1 你的一天

```
登录 → 工作台看应到/已到/待复核 → 课前上传菜谱 → 课上处理异常事件
     → 课后复核（确认/驳回/转复核）→ 归档 → 导出成绩
```

### 4.2 工作台 `/dashboard`

| 区域 | 说明 |
| --- | --- |
| 三级筛选 | 课程 → 班级 → 实训任务；统计范围随筛选变化，右下角有「统计范围随筛选变化」提示 |
| 八张统计卡 | 应到 / 已签到 / 未签到 / 正在实训 / 已完成 / 摄像头在线 / 待复核 / 异常事件，**每张可点进对应页** |
| 当前实训 | 课程、班级、任课教师、实训时间、进度（进行中 / 已完成 / 已归档） |
| 各评价模块完成情况 | 七个模块的数据齐不齐 |
| 待复核名单 | 未归档的学生，点「去归档」直接进综合评价 |
| 近期动态 | 签到、扣分、教师复核记录 |

> 教师工作台**不放**「模块对接进度」——那是交付进度，属于管理员与验收材料。

### 4.3 课程与菜谱 `/courses`

1. 点「上传菜谱」，选 PDF（≤20MB），填课程名、班级、实训目标。
2. 创建后是**草稿**，确认无误再点「发布」——发布后该班学生才会看到。
3. 同一班级同一天只允许一节课（避免时间冲突）。
4. 点进详情可以「让 AI 读一遍」，生成难点与易错点标注；学生看到的是标注结果。

### 4.4 班级名单与白名单导入 `/classes`

**位置**：教学 → 班级名单（不在系统管理，因为这是任课教师开学第一件事）。

| 步骤 | 操作 |
| --- | --- |
| 1 | 左侧选班级，右侧看在册名单（学号、姓名、工位、人脸底库、本节签到） |
| 2 | 点「导入白名单」，把教务名单粘贴进文本框，或点「选择 CSV 文件」 |
| 3 | 点「校验名单」——逐行给出「可创建 / 已存在 / 不合法 + 原因」，先看清楚再提交 |
| 4 | 确认无误点「确认导入 N 人」，返回批次号 |

规则（很重要，避免重复劳动）：

- **库里已有的学号一律跳过，不覆盖**——你手工改过的资料不会被一次导入冲掉。
- 学号必须 8~14 位数字；姓名不能为空、不能是纯数字（列错位的信号）；手机号可留空。
- 缺列也能识别：`2023010154（空）13800000053` 会判「缺少姓名」，不会把手机号当名字存进去。
- 导入的学生默认「待开通」，首次登录时自助采集人脸；没采集的不能人脸签到，只能你代签。

### 4.5 评价模块的通用操作：先选人

着装、食材、烹饪、成品四页顶部**第一件事是选人**：

- 下拉里是本节课在评学生（头像 + 姓名 + 学号后四位 + 是否已签到）；
- 左右箭头可快速切上一个/下一个；
- **一节课跟着人走**：从着装切到成品不用重选，切模块保持同一个人；
- 切人时上一名学生的采样结果会清空，避免串号。

选完之后，画面区显示的是**这个学生的工位录像**，不是你自己对着镜头。所有判定、扣分、归档都记在他名下。

> 综合评价页例外：它本身就是一整张班级名单，不需要先选人。

### 4.6 各模块你能做什么

| 页面 | 你能做的事 |
| --- | --- |
| 人脸签到 | 看全员签到记录、按班级/学号筛选、**人工补签**（必须写原因）、人脸底库管理 |
| 着装规范 | 看五项判定与抓拍、驳回误判（写原因，会留「教师驳回 · 姓名 · 时间」） |
| 食材预处理 | 看切配频率序列与均匀度、调整判定 |
| 烹饪过程 | 看四路通道状态、六步时序、确认异常事件、改判步骤、开/关语音播报 |
| 菜肴成品 | 看五维评分、**教师改分**（保留 AI 原分）、确认/驳回/转复核 |
| 综合评价 | 看名单与环节分、溯源改分、确认/驳回/转复核、归档、导出 |

### 4.7 综合评价与复核（核心流程）

#### ① 复核三态

| 状态 | 含义 | 下一步 |
| --- | --- | --- |
| 待复核（pending） | AI 已给建议分，等你判断 | 确认 / 驳回 / 转复核 |
| 已确认（confirmed） | 你认可这个分 | **可以归档** |
| 已驳回（rejected） | 你不认可，已写原因 | 学生可看到原因，需重新评价 |
| 转复核（reviewing） | 需要教研组或他人再看 | 等待处理 |

**驳回与转复核必须写原因（≥4 个字）**。原因会显示在学生端——这是学生信服的前提。

#### ② 归档

点「归档当前成绩」。**只有「已确认」的记录能归档**，否则会被拒绝——这是硬约束，
因为归档后分数冻结，没确认就归档等于复核白做。

归档之后：分数不能再改，按钮显示「已归档，不可变更」。

#### ③ 成绩溯源与改分（发现分数不对时）

```
点某个环节行  →  右侧抽屉：这个环节的每条来源记录（模块 / 时间 / 单条分 / 抓拍图）
              →  点某条记录：弹窗看明细（快照大图、各维度、元数据）
              →  改分数 + 填原因 → 保存
              →  环节分自动重算，页面下方「成绩修改记录」多一行（含原值）
```

> 改的是**最原始那条记录**，不是环节分。这样任何人问「这 88 分怎么来的」都能一路查到抓拍。

#### ④ 导出

| 按钮 | 结果 | 用途 |
| --- | --- | --- |
| 导出班级成绩 / 导出全站成绩 | CSV，Excel 双击打开 | 批量录入教务系统 |
| 导出当前报告 / 导出我的报告 | 浏览器打印页（A4，一页一人） | 存档、发给学生、家长会 |

学号是文本格式，Excel 里不会变成科学计数法；中文不会乱码。

### 4.8 语音播报（烹饪过程页）

- 右下角开关 + 音量 + 策略（仅严重 / 全部 / 静音）+ 播报带工位号。
- 首次使用需要**先在页面上点一下**（浏览器限制：没有用户操作不允许自动发声）。
  状态栏会写「已开启 · 首次播报前请点击页面一次」。
- 设置会本地保存：**断网、摄像头挂掉都不影响开关**，此时会提示「尚未同步到服务器」。
- 试听按钮可以立刻验证音量。

### 4.9 个人中心 `/profile`

教师看到：登录账号、教研室、手机号、邮箱、开通时间、上次登录；
右侧是**本周课表**（按星期分组）与**班级成绩概览**（各班均分、待复核数，点「查看」进综合评价）。

教师不显示人脸照片（不参与人脸签到）与「我的成绩」（教师没有成绩）。

## 5. 管理员手册

管理员管账号与系统，**不参与评分、不替教师打分**，也没有 AI 助手。

### 5.1 用户管理 `/system/user`

| 操作 | 说明 |
| --- | --- |
| 新增 | 填姓名、账号、角色、手机、邮箱；学生需带学号与班级 |
| 编辑 | 改姓名/联系方式/状态；角色变更要谨慎（会改变其可见范围） |
| 删除 | 二次确认；有成绩记录的账号建议「停用」而不是删除 |
| 停用 | `status=0`，账号不能登录，历史数据保留 |
| 人脸照片 | 行内**只有编辑/删除**；照片维护在「档案抽屉」里点「更换人脸照片」（摄像头或上传） |

> 之前行内那个「补录照片」按钮已移除：同一件事有两个入口，反而让人分不清哪个生效。

### 5.2 通知发布 `/system/notice`

```
新建通知（标题 / 类型 / 接收对象 / 正文 / 是否置顶）→ 保存为草稿
  → 检查无误点「发布」→ 学生/教师端三处立即可见
  → 发错了点「撤回」，回到草稿，接收端立即消失
```

| 字段 | 建议写法 |
| --- | --- |
| 类型 | 系统公告（制度/要求）、功能更新（新功能）、维护通知（停机） |
| 接收对象 | 全站，或只发给教师 / 学生 / 管理员（如教研调整只发教师） |
| 正文 | 写清楚「什么时候、影响谁、需要做什么」，空行分段 |
| 置顶 | 只有一条建议置顶，置顶多了等于没置顶 |

**发布后在哪能看到**：顶栏 🔔 铃铛（最近 5 条 + 未读红点）、学生/教师工作台的公告卡、
公告中心 `/notices`（全部公告，可筛未读）。三处是同一份数据，不会不同步。

统计里的「平均阅读率」= 已读人次 / 应读人数。应读人数按接收对象实时算（全站 / 指定角色）。

### 5.3 工位与设备 `/system/device`

| 表 | 内容 |
| --- | --- |
| 工位 | 空闲 / 使用中 / 维护 / 停用，可改状态 |
| 摄像头 | 在线 / 离线 / 异常 / 停用；绑定工位、启停、**连接测试**（返回 fps 与延迟） |
| 操作记录 | 每次绑定、解绑、启停、测试失败都留痕 |

> 「在线」判定以连接测试真的拉到流为准，不是 ping 得通就算在线。

### 5.4 工作台的「模块交付进度」

管理员首屏看到的是账号构成与七个模块的交付进度——那是给验收看的，不是给教师看的。
教师工作台不会显示这块，避免混淆。

## 6. 常见问题（FAQ）

### 6.1 账号与登录

**Q：忘记密码怎么办？**
A：登录页「忘记密码」会提示联系管理员；管理员在用户管理里重置。系统不做短信找回（校内账号体系统一管理）。

**Q：登录后一直跳回登录页？**
A：三种可能：① token 过期（重新登录）；② 后端未启动或接口地址不对（联系管理员看 `VITE_API_BASE_URL`）；
③ 账号被停用。若页面顶部写着「演示模式」但仍跳回，是生产包跑了 Mock，见 `README.md` 的说明。

**Q：为什么我看不到某个菜单？**
A：菜单按角色过滤，这是设计而非故障。学生没有「评价总览」「班级名单」「系统管理」；
管理员没有 AI 助手。

### 6.2 签到

**Q：摄像头打不开？**
A：① 浏览器地址栏的摄像头图标 → 允许；② 别的软件（腾讯会议、OBS）占用了摄像头，先关掉；
③ 换 Chrome；④ 笔记本有物理遮挡开关。

**Q：识别不出来？**
A：光线不足、侧脸、戴口罩都会影响。让脸占满框、正对镜头。都不行就让教师人工补签。

**Q：为什么学生看不到全班签到记录？**
A：隐私边界。学生只能看自己，教师与管理员才能看全员。

### 6.3 成绩

**Q：分数和我预期不一样怎么办？**
A：点开那个环节行，看每条来源记录（时间 + 抓拍），确认是哪一次判定有问题；
然后找任课教师复核或改分。这是本系统「可溯源」的意义。

**Q：为什么归档后改不了？**
A：归档 = 冻结，防止事后改分引发争议。需要更正时由教师走「成绩修改记录」留痕改分。

**Q：导出 CSV 打开是乱码？**
A：文件带 UTF-8 BOM，正常双击不会乱码。若用旧版 WPS，选「数据 → 从文本导入 → UTF-8」。

**Q：报告打印出来两页？**
A：打印页已按 A4 一页排版。若出现两页，检查是否在打印设置里改过缩放（应保持 100% 或「适合页面」）。

### 6.4 通知

**Q：管理员发布了公告，我这边没看到？**
A：① 检查接收对象是否包含你的角色（只发教师的公告，学生看不到）；② 刷新页面；
③ 确认点的是「发布」而不是只「创建草稿」（草稿对接收端不可见）。

**Q：红点一直不消失？**
A：点开那条公告即标记已读；或点铃铛里的「全部已读」。已读状态按账号保存，换浏览器会重新计未读。

### 6.5 其他

**Q：刷新页面后数据回到原样？**
A：演示模式（Mock）下成绩类数据不落库，刷新会回到演示初始态；公告这类会记住。
连上真实后端后一切以数据库为准。

**Q：页面出现「接口未对接」的灰条？**
A：该模块的接口还没接上后端，属于交付进度问题，不是你的操作问题。可以先用演示数据走流程。

**Q：能不能手机上用？**
A：可以，页面是响应式的（侧栏会收成抽屉）。人脸签到建议用电脑或平板，手机前置摄像头画质与稳定性一般。

## 7. 十分钟演示脚本（答辩 / 汇报用）

> 目标：让评委在 10 分钟内看到「过程留痕 → 教师复核 → 成绩可溯源」的闭环。

| 时间 | 角色 | 操作 |
| --- | --- | --- |
| 0:00 | 学生 | 登录 → 工作台：指出四张卡、本节课、环节得分条（显示进行中的环节） |
| 1:00 | 学生 | 人脸签到：刷脸成功，提示姓名与相似度；强调「只能看到自己的记录」 |
| 2:00 | 学生 | 菜肴成品：上传一张成品照 → 五维评分 + 建议分 + 免责说明 |
| 3:00 | 教师 | 切换账号登录 → 工作台：应到/已到/待复核八张卡，点「待复核」进综合评价 |
| 4:00 | 教师 | 综合评价：名单里的三态（待复核/已确认/已驳回），点一条环节行 |
| 5:00 | 教师 | 溯源抽屉 → 点某条来源 → 弹窗看抓拍 → **改分并填原因** |
| 6:30 | 教师 | 指出「成绩修改记录」多了一行，原值仍可查（这是可追溯的证据链） |
| 7:00 | 教师 | 确认 → 归档；再点一次归档提示「已归档，不可变更」 |
| 8:00 | 教师 | 导出班级成绩 CSV + 打开一人报告（A4 打印页） |
| 9:00 | 管理员 | 登录 → 通知发布：新建 → 发布 → 切回教师端看铃铛立即出现 |
| 9:40 | — | 收尾：强调边界「AI 只给建议分，教师确认才生效」 |

**演示前检查清单**：浏览器只开一个标签、摄像头可用、演示数据已重置（清 `localStorage`）、
网络无关（全程 Mock 也能演完）。

## 8. 术语表

| 术语 | 说明 |
| --- | --- |
| 环节 | 综合评价的五个组成部分：签到与着装、食材预处理、烹饪过程、菜肴成品、课堂问答 |
| 权重 | 环节占总分的比例，合计 100%；由接口下发，不写死 |
| 来源记录 | 环节分背后的原始记录（一次签到、一个事件、一张成品照） |
| 复核三态 | 待复核 / 已确认 / 已驳回（+ 转复核） |
| 归档 | 冻结分数并留存快照，之后不可变更 |
| 代签 | 教师为无法人脸签到（未录入、设备故障）的学生人工补签，需写原因 |
| 白名单 | 从教务导出的班级名单，用于开通学生账号 |
| 演示模式 | 使用内置示例数据运行，不连后端；页面右上角有提示 |
| 智能 AI 老师 / 助手 | 同一个功能：学生端叫「老师」，教师与管理员端叫「助手」 |
