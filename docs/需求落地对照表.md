## 附：缺口与优化建议

### 必须知道的三个「不是 bug」

1. **所有 AI 判定都是前端模拟**。`backend/` 目录目前只有 `requirements.txt`，`POST /face/checkin`、`/modules/*/analyze`、`/ws/cooking` 全部走 `VITE_USE_MOCK=true` 的本地数据。接口契约以各页右侧「接口」面板和 `docs/后端开发任务书.md` 为准，接后端时只替换 `api/*.ts` 里的 mock 分支，页面代码不动。
2. **烹饪四路视频没有真实播放**. 通道状态、fps、延迟、事件都是真的，但画面是占位（第一路用本机摄像头演示）。真实推流需要后端给 HLS / WebRTC 地址，前端再装 `hls.js` 或在 `<video>` 上挂 `src`。
3. **生产包看不到页面**是设计使然（第 1 章要求生产禁 Mock），演示请用 `npm run dev`。

### 按优先级排的优化项

**P0 · 接后端时一定会踩的**

- 接口响应做运行时校验（`zod` 或手写 guard），避免后端字段改名后页面静默变空。
- 为 `POST /files`、`/chat`、`/cooking` 三条链路补集成测试，Mock 与真实后端各跑一遍同一组断言。

**P1 · 甲方验收会问到的**

- **任务管理页**（缺口 1）：需后端先建 `tasks` 表。前端可复用课程页的「列表 + 表单弹窗」结构，加 `/tasks` 路由与 `tasks:manage` 能力点。
- **视频播放器**：接后端推流后，给 `CameraChannel` 加 `streamUrl`，封装 `components/StreamPlayer.vue`（HLS 用 `hls.js` 动态 import，失败回落到「重连」态）。
- **导出升级**：CSV → 服务端 `openpyxl` 生成 xlsx（保留列宽与样式）；打印页 → 服务端 `weasyprint` 出 PDF（避免用户手动 Ctrl+P，也便于批量导出）。

**P2 · 顺手可做**

- 列表接 `sort-change`（缺口 2）：`el-table` 加 `sortable="custom"`，`@sort-change` 写回 `query.sortBy / order` 再请求；数据量大时换 `el-table-v2` 虚拟滚动。
- 筛选条件写入 URL query（`router.replace`），刷新与分享不丢状态。
- 页面级 `onErrorCaptured` + 全局错误上报，避免单块组件异常白屏。
- 打印页支持长名单分页（`break-inside: avoid` + 每页表头重复）。
- 深色模式：令牌已集中在 `variables.scss`，加一组 `[data-theme='dark']` 覆盖即可，无需改组件。
