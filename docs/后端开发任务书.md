## 3. 全局约定

### 3.1 统一响应

前端 `utils/request.ts` 会自动拆包，**只取 `data`**，`code != 0` 直接抛错。所以：

```json
{ "code": 0, "data": { }, "message": "ok" }
```

| code | 含义 | HTTP 状态码 |
| --- | --- | --- |
| 0 | 成功 | 200 |
| 40001 | 参数校验失败 | 422 |
| 40100 | 未登录 / token 失效 | 401 |
| 40300 | 角色无权访问 | 403 |
| 40400 | 资源不存在 | 404 |
| 40900 | 冲突（用户名重复、重复归档） | 409 |
| 50000 | 服务端异常 | 500 |

**不要**只靠 HTTP 200 + `code != 0`，也不要只靠状态码——两者都带上，前端两种都能处理。

### 3.2 字段命名：camelCase

前端 TS 类型就是契约，字段名必须是 camelCase：`studentNo`、`className`、`archivedAt`、`checkinRate`。
数据库列用 snake_case，在 pydantic 层转换：

```python
from pydantic import BaseModel, ConfigDict
from pydantic.alias_generators import to_camel

class CamelModel(BaseModel):
    model_config = ConfigDict(alias_generator=to_camel, populate_by_name=True, from_attributes=True)
```

> 七个模块页右侧的「接口面板」里有些示例写成 snake_case，那是文档笔误，
> 以 `frontend/src/types/` 为准，**统一 camelCase**。

### 3.3 时间

- 统一字符串 `YYYY-MM-DD HH:mm`（不带 T、不带时区后缀），前端直接用 `dayjs` 解析。
- DB 用 `DATETIME`，连接串加 `?charset=utf8mb4`，MySQL 时区设 `+08:00`。
- 不要返回 `2026-11-21T05:35:00.000Z`，会显示成少 8 小时。

### 3.4 分页

```json
{ "list": [], "total": 42, "page": 1, "pageSize": 20 }
```

### 3.5 鉴权

```
Authorization: Bearer <token>
```

登录成功返回：

```json
{ "code": 0, "data": { "token": "eyJ...", "user": { "id": 2, "name": "陈立群", "role": "teacher" } } }
```

`role` 只能是 `student | teacher | admin`。

### 3.6 上传限制

| 类型 | 字段 | 上限 | 说明 |
| --- | --- | --- | --- |
| 人脸照片 | `file` | 5MB | jpg/png，前端已压到 480px |
| 成品图 | `file` | 4MB | jpg |
| 菜谱 | `file` | 20MB | 仅 PDF |

超限返回 `40001`，`message` 写清楚（「图片不能超过 4MB」），前端会原样弹出来。

## 4. 权限

前端唯一事实来源是 `frontend/src/config/permissions.ts`，后端照它写死一份，别自己发挥：

| 能力 | 学生 | 教师 | 管理员 |
| --- | --- | --- | --- |
| 看自己的成绩 `GET /v1/dashboard/me`、`/v1/summary/{id}/report` | ✅ 仅本人 | ✅ | ✅ |
| 班级名单 `GET /v1/summary/roster` | ❌ | ✅ | ✅ |
| 模块内扣分 `POST /v1/modules/.../deductions` | ❌ | ✅ | ✅ |
| 归档 `POST /v1/summary/{id}/archive` | ❌ | ✅ | ✅ |
| 上传课程 `POST /v1/courses` | ❌ | ✅ | ✅ |
| 用户管理 `/v1/users*` | ❌ | ❌ | ✅ |
| 通知发布 `/v1/notices`（写） | ❌ | ❌ | ✅ |
| 问答 `POST /v1/chat` | ✅ | ✅ | ❌ |

依赖注入写法：

```python
def require_roles(*roles: str):
    def _dep(user: User = Depends(get_current_user)) -> User:
        if user.role not in roles:
            raise ApiError(40300, "无权访问", status=403)
        return user
    return _dep

@router.get("/v1/users")
def list_users(_: User = Depends(require_roles("admin"))): ...
```

**三条最容易写错的边界**

1. 学生请求 `GET /v1/summary/{id}/report` 时，`id` 必须等于本人，否则 403（前端也拦了一道，但后端必须拦）。
2. 学生的 `GET /v1/summary/roster` 一律 403，不要"返回只含他自己的一条"——接口语义不同。
3. `POST /v1/chat` 管理员不可用（`assistant.use` 不含 admin）。

## 5. 数据库

字符集统一 `utf8mb4` + `utf8mb4_0900_ai_ci`（MySQL 8），引擎 InnoDB。
下面是核心表，**可以直接执行**；字段注释里标了对应的前端类型字段。

```sql
CREATE DATABASE IF NOT EXISTS culinary
  DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_0900_ai_ci;
USE culinary;

-- 账号 ------------------------------------------------------------------
CREATE TABLE users (
  id            BIGINT PRIMARY KEY AUTO_INCREMENT,
  username      VARCHAR(64)  NOT NULL UNIQUE,        -- 学生用学号
  password_hash VARCHAR(128) NOT NULL,
  name          VARCHAR(32)  NOT NULL,
  role          ENUM('student','teacher','admin') NOT NULL,
  student_no    VARCHAR(32)  NULL,
  phone         VARCHAR(20)  NULL,
  email         VARCHAR(128) NULL,
  department    VARCHAR(64)  NULL,                   -- 「烹饪工艺与营养 2301」
  face_photo    VARCHAR(255) NULL,                   -- 人脸底库 URL
  face_registered TINYINT(1) NOT NULL DEFAULT 0,
  status        TINYINT      NOT NULL DEFAULT 1,      -- 1 启用 0 停用
  created_at    DATETIME     NOT NULL DEFAULT CURRENT_TIMESTAMP,
  last_login_at DATETIME     NULL,
  KEY idx_role (role), KEY idx_student_no (student_no)
) ENGINE=InnoDB;

-- 班级与花名册 ----------------------------------------------------------
CREATE TABLE classes (
  id   BIGINT PRIMARY KEY AUTO_INCREMENT,
  name VARCHAR(64) NOT NULL UNIQUE                    -- 「烹饪工艺与营养 2301」
) ENGINE=InnoDB;

CREATE TABLE class_students (
  class_id   BIGINT NOT NULL,
  user_id    BIGINT NOT NULL,
  seat       VARCHAR(8) NOT NULL,                     -- 工位号，前端 SummaryStudent.seat
  PRIMARY KEY (class_id, user_id)
) ENGINE=InnoDB;

-- 课程与菜谱 ------------------------------------------------------------
CREATE TABLE courses (
  id          BIGINT PRIMARY KEY AUTO_INCREMENT,
  title       VARCHAR(128) NOT NULL,
  class_id    BIGINT NOT NULL,
  teacher_id  BIGINT NOT NULL,

  dishes      JSON NULL,                              -- ["糖醋里脊","上汤娃娃菜"]
  lesson_at   DATETIME NOT NULL,

-- 实训任务（一节课 = 一个 task，所有评价记录挂在它下面）----------------
CREATE TABLE tasks (
  id          VARCHAR(32) PRIMARY KEY,                -- "task_20261121_01"
  course_id   BIGINT NOT NULL,

-- 签到 ------------------------------------------------------------------
CREATE TABLE checkins (
  id          BIGINT PRIMARY KEY AUTO_INCREMENT,

  image_url   VARCHAR(255) NULL,
  checked_at  DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  UNIQUE KEY uk_task_student (task_id, student_id)
) ENGINE=InnoDB;

-- 各模块判定结果（一个模块一个 JSON，够用且好扩展）--------------------
CREATE TABLE module_results (
  id          BIGINT PRIMARY KEY AUTO_INCREMENT,
  task_id     VARCHAR(32) NOT NULL,
  student_id  BIGINT NOT NULL,
  module      VARCHAR(24) NOT NULL,                   -- uniform/ingredient/cooking/dish
  score       DECIMAL(5,1) NOT NULL,
  detail      JSON NOT NULL,                          -- 该模块的判定明细
  created_at  DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  UNIQUE KEY uk_task_student_module (task_id, student_id, module)
) ENGINE=InnoDB;

-- 教师现场扣分（与学生成绩分开存，谁扣的、为什么扣都要留痕）------------
CREATE TABLE deductions (
  id          BIGINT PRIMARY KEY AUTO_INCREMENT,
  task_id     VARCHAR(32) NOT NULL,
  student_id  BIGINT NOT NULL,
  module      VARCHAR(24) NOT NULL,
  item        VARCHAR(64) NOT NULL,                   -- 违规项，如「未戴厨师帽」
  points      INT NOT NULL,
  reason      VARCHAR(255) NOT NULL,
  created_by  BIGINT NOT NULL,                        -- teacher id
  created_at  DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  KEY idx_task_student (task_id, student_id)
) ENGINE=InnoDB;

-- 综合评价与归档快照 ----------------------------------------------------
CREATE TABLE summaries (
  id          BIGINT PRIMARY KEY AUTO_INCREMENT,
  task_id     VARCHAR(32) NOT NULL,
  student_id  BIGINT NOT NULL,
  weighted    DECIMAL(5,1) NOT NULL,                  -- 加权分（未扣教师分）
  deducted    INT NOT NULL DEFAULT 0,
  total       INT NOT NULL,                           -- 最终分
  grade       VARCHAR(8) NOT NULL,                    -- 优秀/良好/中等/及格/不及格
  stages      JSON NOT NULL,                          -- [{key,label,weight,score,records}]

  archived_at DATETIME NULL,
  UNIQUE KEY uk_task_student (task_id, student_id)

CREATE TABLE summary_snapshots (
  id          BIGINT PRIMARY KEY AUTO_INCREMENT,
  summary_id  BIGINT NOT NULL,
  payload     JSON NOT NULL,                          -- 归档当时的完整成绩，之后权重调整不影响
  created_at  DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP
) ENGINE=InnoDB;

-- 通知与问答 ------------------------------------------------------------
CREATE TABLE notices (
  id         BIGINT PRIMARY KEY AUTO_INCREMENT,
  title      VARCHAR(128) NOT NULL,
  body       TEXT NOT NULL,
  level      ENUM('info','warning','success') NOT NULL DEFAULT 'info',
  status     ENUM('draft','published','revoked') NOT NULL DEFAULT 'draft',
  created_by BIGINT NOT NULL,
  created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  published_at DATETIME NULL
) ENGINE=InnoDB;

CREATE TABLE chat_sessions (
  id         BIGINT PRIMARY KEY AUTO_INCREMENT,
  user_id    BIGINT NOT NULL,
  title      VARCHAR(64) NOT NULL,
  created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP
) ENGINE=InnoDB;

CREATE TABLE chat_messages (
  id         BIGINT PRIMARY KEY AUTO_INCREMENT,
  session_id BIGINT NOT NULL,
  role       ENUM('user','assistant') NOT NULL,
  content    MEDIUMTEXT NOT NULL,
  file_url   VARCHAR(255) NULL,
  created_at DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP,
  KEY idx_session (session_id)

-- 官网留资 --------------------------------------------------------------
CREATE TABLE demo_requests (
  id          BIGINT PRIMARY KEY AUTO_INCREMENT,
```

## 6. 接口清单

路径都省了 `/api` 前缀（你的 router 前缀是 `/api`）。**"状态"列的 Mock 指的是前端本地假数据，不是你的进度。**

### 6.1 账号与鉴权

| 方法 | 路径 | 入参 | 返回 | 权限 |
| --- | --- | --- | --- | --- |
| POST | `/v1/auth/login` | `{username,password}` | `{token,user}` | 公开 |
| GET | `/v1/auth/profile` | — | `User` | 登录 |
| POST | `/v1/auth/logout` | — | `null` | 登录 |
| POST | `/v1/auth/register` | `{username,password,name,role,phone,facePhoto?}` | `{id,username,needApproval}` | 公开 |
| GET | `/v1/users` | `page,pageSize,keyword,role,status` | `PageResult<User>` | admin |
| POST | `/v1/users` | `UserForm` | `User` | admin |
| PUT | `/v1/users/{id}` | `UserForm` | `User` | admin |
| DELETE | `/v1/users/{id}` | — | `null` | admin |
| PUT | `/v1/users/{id}/face` | `{facePhoto}` (dataURL) | `null` | admin |

注册注意：`student` 角色 `needApproval=true`，账号 `status=0` 等管理员审核；`teacher` 同理。
**注册必须校验用户名唯一**，前端只会把后端的错误信息弹出来（`40900` + `该账号已存在，请更换用户名`）。

### 6.2 工作台

| 方法 | 路径 | 返回 | 权限 |
| --- | --- | --- | --- |
| GET | `/v1/dashboard/overview` | `DashboardOverview` | teacher, admin |
| GET | `/v1/dashboard/me` | `MyOverview` | student |

`MyOverview` 只能含本人数据（`stats / stages / todos / activities`），**不要**把班级签到率塞进去。

### 6.3 课程

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET | `/v1/courses` | 教师看自己上传的，学生看本班已发布的 |
| POST | `/v1/courses` | `multipart/form-data`：`title,classId,goal,dishes,lessonAt,file` |
| GET | `/v1/courses/{id}` | 课程详情 |
| DELETE | `/v1/courses/{id}` | 教师本人或管理员 |
| POST | `/v1/courses/{id}/publish` | 发布，学生才看得到 |
| GET | `/v1/courses/{id}/recipe` | 菜谱结构化内容（`RecipeDoc`） |
| POST | `/v1/courses/{id}/analyze` | 解析菜谱，返回难点/易错点，超时给 60s |

`POST /analyze` 返回的 `insights[].step` 必须与 `recipe.steps[].index` 对齐，
否则前端「难点标注」会落错行（前端已按这个约束渲染）。

### 6.4 通知

| 方法 | 路径 | 权限 |
| --- | --- | --- |
| GET | `/v1/notices` | 登录（学生只看已发布） |
| GET | `/v1/notices?scope=manage` | admin（含草稿） |
| POST/PUT/DELETE | `/v1/notices[/{id}]` | admin |
| POST | `/v1/notices/{id}/publish`、`/revoke` | admin |
| GET | `/v1/notifications` | 登录，返回未读角标用的列表 |

### 6.5 七个评价模块

| 模块 | 接口 | 说明 |
| --- | --- | --- |
| 人脸签到 | `POST /face/checkin`（`file`,`userId?`）、`GET /face/records?limit=` | 返回 `{passed,similarity,student,checkedAt}` |
| 着装 | `POST /v1/modules/uniform/analyze`、`GET /v1/modules/uniform/records` | 五项判定：帽子/上衣/围裙/袖口/发网 |
| 食材 | `POST /v1/modules/ingredient/analyze`、`GET /v1/modules/ingredient/frame` | 切丝频率序列 |
| 烹饪 | `WS /ws/cooking`、`GET /v1/modules/cooking/segments` | 六步分段与计时 |
| 成品 | `POST /v1/modules/dish/analyze`、`GET /v1/modules/dish/rubric` | 五维加权 + 评语 |
| 综合评价 | 见 6.6 | 本文新增 |
| 问答 | `POST /v1/chat`（SSE）、`POST /v1/files`、`GET/DELETE /v1/chat/sessions[/{id}]` | 见第 8 节 |

每个模块页右侧面板里都有完整的请求体/响应体，**照着那个结构返回就行**，字段名改成 camelCase。

### 6.6 综合评价（本次新增，重点）

```http
GET /v1/summary/roster?taskId=task_20261121_01&classId=12
```

教师 / 管理员。返回任务信息 + 名单 + 各环节得分，结构见
`frontend/src/types/summary.ts` 的 `SummaryRoster`：

```json
{
  "code": 0,
  "data": {
    "task": {
      "id": "task_20261121_01",
      "courseTitle": "《中式热菜制作》—— 糖醋里脊",
      "className": "烹饪工艺与营养 2301",
      "lessonAt": "2026-11-21 08:00",
```

教师 / 管理员。锁定分数、写 `summary_snapshots`，返回 `{ archivedAt, snapshotId }`。

**归档规则**

1. `total < 60` 时可以先要求复核：后端返回 `40900` + `低于 60 分需复核后再归档`，前端会照弹。
2. 归档后权重表调整**不得**影响历史成绩——快照就是为了这个。
3. 归档是幂等的边界：教师重复点不该产生两份快照。

## 7. 导出：成绩单与报告

前端已经实现了两个导出，**不依赖后端**：

| 导出 | 形式 | 前端实现位置 |
| --- | --- | --- |
| 成绩单（班级 / 全站 / 我的） | CSV，Excel/WPS 双击打开 | `utils/export.ts` → `downloadCsv()` |
| 单人报告 | A4 打印页，浏览器「另存为 PDF」 | `views/modules/summary/report.vue` |

**方案 A（默认，推荐）：后端不用写导出。** 数据由 6.6 的接口提供，前端即时生成，天然与屏幕一致。

**方案 B：后端发 xlsx。** 想统一服务端生成、或要带公章图片时用这个：

```python
# GET /v1/summary/export?taskId=&classId=  权限：teacher/admin；学生另开 /v1/summary/me/export
@router.get("/v1/summary/export")
def export_scores(taskId: str, classId: int | None = None, user=Depends(require_roles("teacher","admin"))):
    wb = build_workbook(taskId, classId)          # openpyxl
    buf = BytesIO(); wb.save(buf); buf.seek(0)
    filename = quote(f"综合评价-{class_label}-{date}.xlsx")
    return StreamingResponse(
        buf,
        media_type="application/vnd.openxmlformats-officedocument.spreadsheetml.sheet",
        headers={"Content-Disposition": f"attachment; filename*=UTF-8''{filename}"},
    )
```

前端切换到方案 B 只需要把 `downloadCsv(...)` 换成「请求 blob → `downloadBlob()`」，一处改动。

**方案 C：后端发 PDF。** 只有「必须服务端存档」时才做。中文字体是坑：WeasyPrint 需要显式注册
`Noto Sans CJK`，reportlab 需要 `TTFont` 指定 `.ttf`，否则中文全变方块。为了一个报告引 100MB 字体不划算。

**导出必须守的三条**

1. 学生只能导自己（`studentId` 从 token 取，不接受前端传）。
2. 学号是文本，别让 Excel 转成数字（openpyxl 设 `cell.number_format = '@'`）。
3. 文件名带范围与日期：`综合评价-烹饪工艺与营养2301-20261121.csv`。

## 8. 流式问答（SSE）的四条硬要求

前端 `utils/sse.ts` 用的是 `fetch + ReadableStream`，不是 `EventSource`（要带 Authorization 与 POST body）。

1. **响应头**：`Content-Type: text/event-stream`、`Cache-Control: no-cache`、`X-Accel-Buffering: no`。
2. **不要缓冲**：Nginx 要关 `proxy_buffering`；FastAPI 用 `StreamingResponse`，别先拼完整字符串。
3. **数据格式**：每帧 `data: {"delta":"…"}\n\n`，结束发 `data: [DONE]\n\n`。前端按 `delta` 追加。
4. **超时与中断**：客户端断开要能感知（`await request.is_disconnected()`），及时释放模型调用。

附件问答：前端先 `POST /v1/files` 拿 `file_id`，再随 `/v1/chat` 的 `fileIds` 发送（camelCase）。
后端要把文件内容转成文本/图片喂给模型，**不要把 file_id 直接丢给模型**。

## 11. 常见坑（都是踩过的）

| 现象 | 原因 | 处理 |
| --- | --- | --- |
| 前端所有请求 404 | 路由前缀漏了 `/api` | `app.include_router(r, prefix="/api")` |
| 浏览器报 CORS | 只开了 `allow_origins=["*"]` 但 `allow_credentials=True` | 显式列 5173 |
| 中文变 `???` | 表/连接不是 utf8mb4 | 库、表、连接串三处都要 |
| 时间少 8 小时 | 返回了 ISO UTC | 统一 `YYYY-MM-DD HH:mm` + `Asia/Shanghai` |
| CSV 打开乱码 | 没写 BOM | 文件头 `\ufeff` |
| pydantic 报 `field required` 但前端明明传了 | 用了 alias 但没 `populate_by_name` | 见 3.2 |
| 上传 413 | 没设 `MAX_UPLOAD_MB` 或 Nginx `client_max_body_size` | 两处都要改 |
| 学生能看到全班成绩 | 只在前端 `v-if` 挡了 | 后端必须再判一次 |
| SSE 一次性吐出全部 | 中间层缓冲 | 见第 8 节 |
