## 1. 十分钟跑起来

### 1.1 环境要求

| 工具 | 版本 | 说明 |
| --- | --- | --- |
| Node.js | ≥ 20.19（实测 22.22 正常） | `node -v` 检查 |
| 包管理 | pnpm / npm 均可 | 仓库同时存在 `pnpm-lock.yaml` 与 `package-lock.json`，**只用一种** |
| Python | 3.11+ | 仅后端需要 |

### 1.2 启动

```bash
cd frontend
pnpm install            # 或 npm install
pnpm dev                # 默认 http://localhost:5173
```

后端（可选，未启动时用 Mock 也能跑全站）：

```bash
cd backend
python -m venv .venv && source .venv/bin/activate   # Windows: .venv\Scripts\activate
pip install -r requirements.txt
uvicorn app.main:app --reload --port 8000
```

### 1.3 四条命令的分工

| 命令 | 作用 | 什么时候用 |
| --- | --- | --- |
| `pnpm dev` | 开发服务器，热更新 | 写代码时 |
| `pnpm type-check` | `vue-tsc --noEmit`，只查类型 | **每次提交前必跑** |
| `pnpm build` | 先 type-check 再打包到 `dist/` | 交付、部署前 |
| `pnpm preview` | 预览生产包（4173 端口） | 验证包体行为，**注意 Mock 已关闭** |

> `pnpm build` 里带 `vue-tsc`，所以类型错误会直接让构建失败。这是故意的：
> 类型错在白屏之前就被挡住。

## 2. 目录结构与职责

```
frontend/
├── src/
│   ├── api/            # 接口层：一个业务域一个文件，Mock 分支写在同一文件内
│   ├── assets/
│   │   ├── images/     # 实拍照片（faces/ 是人脸底库示例）
│   │   └── styles/     # variables / base / element-override / motion / site
│   ├── components/      # 跨页面复用件（含 ApiPanel、ModuleShell、NoticeReader…）
│   ├── composables/     # useRole / useCountUp / useCamera…
│   ├── config/          # permissions.ts —— 权限唯一事实来源
│   ├── directives/      # v-reveal / v-parallax / v-stagger
│   ├── layouts/         # SiteLayout（官网）/ AuthLayout（登录）/ DefaultLayout（后台）
│   ├── mock/            # 演示数据，与真实接口同构
│   ├── router/          # index.ts 路由表 / guard.ts 守卫 / menu.ts 侧栏
│   ├── stores/          # Pinia（setup 写法）：auth / notice / face / review / speech…
│   ├── types/           # 全部 TS 类型，即前后端契约
│   ├── utils/           # request / sse / export / format / token / env / confirm
│   └── views/           # 页面，按功能域分目录
├── vite.config.ts       # 别名、SCSS 全局注入、/api 与 /ws 代理、Mock 生产护栏
└── .env.development / .env.production
```

**分层铁律**：`views → stores/api → utils`，**反向依赖禁止**。
`api/*` 不许 import 任何 `.vue`；`utils/*` 不许 import `stores`（除了 token 这种纯工具）。

## 3. 一次请求的完整链路

以「综合评价页加载名单」为例，理解这条链路比读十个文件都有用：

```
views/modules/summary/index.vue
  onMounted → load()
      ↓
api/summary.ts  fetchSummaryRoster(taskId, classId)
  if (USE_MOCK) → mock/summary.ts 造数据（同结构）
  else          → http.get('/summary/roster', params)
      ↓
utils/request.ts
  请求拦截：注入 Authorization
  响应拦截：拆 { code, data, message } → 只把 data 给上边
            code≠0 → ElMessage.error + reject
            401 → 清 token + 跳 /login（并发只跳一次）
      ↓
views：拿到类型化数据 → 渲染；错误已在 request 层提示过，页面只需兜 loading/empty
```

**所以页面里不需要写 try/catch 弹错**（除非要覆盖文案）。页面只需要：
`loading`（骨架屏）、`error`（`StateView state="error"`）、`empty`（`StateView state="empty"`）。

## 4. 接口层规范（`api/*.ts`）

### 4.1 一个接口的标准写法

```ts
import { http } from '@/utils/request'
import { USE_MOCK } from '@/utils/env'
import { mockDelay } from '@/mock'
import type { Notice, NoticeForm } from '@/types'

/** 新建公告 POST /notices */
export async function createNotice(form: NoticeForm): Promise<Notice> {
  if (USE_MOCK) {
    await mockDelay(500)
    // …构造并写入 mock 数组
    return notice
  }
  return http.post<Notice>('/notices', form)
}
```

四条约定：

1. **函数上方一行注释写清楚方法与路径**，这是联调时的第一手资料。
2. **Mock 分支写在同一个函数里**，不要把 Mock 拆到别处——切成真实接口时只改这一处。
3. 返回类型必须显式标注（`Promise<Notice>`），它是页面能编译的前提。
4. 不要在这里做 UI 提示（`ElMessage`），除了「业务错误需要更具体文案」时。

### 4.2 为什么 Mock 写在 api 层而不是拦截器

用 axios 拦截器伪造响应，会让「哪些接口还没接」变得不可见。写在各函数里，
`grep USE_MOCK` 就能列出全部未接接口，交付盘点很方便。

## 5. 状态管理（`stores/*.ts`）

统一用 **setup 写法**，不用 options：

```ts
export const useNoticeStore = defineStore('notice', () => {
  const items = ref<Notice[]>([])
  const unreadCount = computed(() => items.value.filter(/* … */).length)
  async function refresh(force = false) { /* … */ }
  return { items, unreadCount, refresh }
})
```

### 5.1 什么时候该进 store

| 该进 store | 不该进 store |
| --- | --- |
| 跨页面共享（登录用户、公告、当前在评学生） | 只在单页面用的表单字段、弹窗开关 |
| 需要跨组件触发（阅读器弹窗由任意处打开） | 一次性列表数据（直接在页面 `ref`） |
| 需要持久化（`localStorage`）的偏好设置 | 后端已缓存的数据（别做二级缓存） |

### 5.2 现有 store 一览

| store | 负责 | 关键点 |
| --- | --- | --- |
| `auth.ts` | token、当前用户、角色 | `reset()` 在 401 与退出时都调 |
| `app.ts` | 侧栏折叠、移动端抽屉 | **只有 UI 状态**，业务数据不进来 |
| `notice.ts` | 公告列表、已读集合、阅读器开关 | 已读按账号存 localStorage；`loadedFor` 防重复拉取 |
| `face.ts` | 签到、记录分页、学生隔离 | `setScope(studentId)` 后强制按本人过滤 |
| `review.ts` | 当前在评学生 `activeStudentId` | 全模块共享，切人清空采样 |
| `speech.ts` | 语音配置、播报 | 本地缓存 + 一次性手势解锁 |
| `chat.ts` | 会话、流式消息 | 与 SSE 协作 |

### 5.3 反面教材（仓库里真实踩过的）

- **把假数据放进 app store**：早期 `app.ts` 存了一份硬编码通知，导致「管理员发布公告后顶栏毫无变化」。
  业务数据必须从 api → store，不能有第二份。
- **在模板里做数据隔离**：`faceStore.checkin()` 自己会重拉记录，只在模板 `v-if` 过滤，
  签到成功那一刻全班记录会灌回来。隔离要在 store 的请求参数里做。

## 6. 路由与权限

### 6.1 三处协作

| 文件 | 作用 |
| --- | --- |
| `config/permissions.ts` | **唯一事实来源**：能力点 `Capability`、`ROLE_SCOPE`（定位文案）、`MODULE_ACCESS`（七模块矩阵） |
| `router/index.ts` | 路由表，`meta.roles` 声明允许的角色 |
| `router/guard.ts` | 守卫：未登录 → `/login`；角色不符 → 回工作台并提示 |
| `router/menu.ts` | 侧栏菜单，按 `group` 分组，按角色过滤，支持 `titles` 按角色换名 |

### 6.2 页面里怎么判断权限

```ts
const { isStudent, isTeacher, isAdmin, can } = useRole()
```

- 需要「能不能做某个操作」→ `can('summary.review')`
- 需要「按角色换内容」→ `isTeacher` / `isStudent`

**禁止**：`if (role === 'teacher')`、`if (user.role === 'admin')`。新增能力点就改 `permissions.ts`，
不要在页面里加临时判断。

### 6.3 添加一个页面

1. `views/<域>/index.vue` 写页面；
2. `router/index.ts` 加路由，**`meta.title` 必填**（面包屑与 `document.title` 都用它），
   要限制角色就加 `meta.roles`；
3. `router/menu.ts` 加菜单项（不想要菜单入口就别加，比如 `/notices`）；
4. 新能力点 → `permissions.ts` 加 `Capability` + `ROLES` 映射。

## 7. 样式体系（改视觉前必读）

### 7.1 令牌的唯一来源

`assets/styles/variables.scss` 通过 `vite.config.ts` 的 `additionalData` 全局注入，
**任何 `.vue` 的 `<style lang="scss">` 里都能直接用 `$space-4`、`$color-text-primary`**，
不要再写魔法数字。

| 文件 | 内容 |
| --- | --- |
| `variables.scss` | 色彩、间距、字号、圆角、阴影、动效曲线、玻璃令牌、`$bg-ambient` |
| `base.scss` | 复位、`.app-card`、`.page`、`.card-head`、`.meter`、`.tag`、`.empty-line` |
| `element-override.scss` | Element Plus 的外观对齐（表格、弹窗、抽屉、表单） |
| `motion.scss` | `v-stagger`、`.animate-in`、`.status-dot`、骨架屏 |
| `site.scss` | 官网专用（`$site-*`、`.btn`），必须全局 |

### 7.2 五条视觉纪律（写在 variables.scss 头部）

1. **单一强调色**（`$color-primary`），不要第二强调色；
2. **真中性灰**，不要带蓝紫的灰；
3. **禁止装饰性彩条 / 彩色图标块 / 胶囊堆叠**——这是「AI 模板风」的最大特征；
4. **三档阴影**（无 / 静置 / 抬起），不要五档；
5. **动效统一取值**（`$duration-fast/base` + `$ease-standard`）。

状态色只允许出现在 5~6px 的圆点（`.status-dot--success/warning/danger`）上，不铺底色。

### 7.3 玻璃拟态的使用边界

只用在三处：**壳层**（顶栏 / 侧栏）、**卡片层**（`.app-card`）、**弹层**（dialog / drawer）。
环境光只用 3% 级别的径向渐变（`$bg-ambient`），并配 `@supports not (backdrop-filter)` 回落到不透明。
**不要**给正文区、表格行加模糊——那会让文字发灰、可读性下降。

### 7.4 常用件（优先复用，不要重写）

| 组件 | 用途 |
| --- | --- |
| `PageHeader` | 页头：标题 + 事实型副标题 + 操作区 |
| `ModuleShell` | 评价模块版式：左操作区 + 右 340px 接口面板（自动挂 `StudentPicker`） |
| `ApiPanel` / `ApiDrawer` | 接口契约面板 / 抽屉版 |
| `StateView` | `loading / empty / error / forbidden` 四态 |
| `AppSkeleton` | 骨架屏，`variant` 分 `stats/list/table` |
| `StatCard` | 统计卡，支持 `to` 跳转与 `delta`（未定义时整行不渲染） |
| `ReviewActions` | 复核三态操作条（综合评价与成品共用） |
| `StudentPicker` | 教师选人（下拉 + 箭头 + 已签到计数） |
| `ReviewStage` | 该生工位录像替代画面 |
| `NoticeBoard` / `NoticeReader` | 公告卡 / 公告阅读器 |

## 8. Mock 机制与切换真实接口

### 8.1 开关链路

```ini
# .env.development
VITE_USE_MOCK=true
VITE_API_BASE_URL=/api/v1
```

```ts
// utils/env.ts
export const USE_MOCK = mockRequested && (!IS_PROD || allowMockInProd)
```

**双保险**：

- 运行期：生产环境即使写了 `true` 也不生效，除非再设 `VITE_ALLOW_MOCK_IN_PROD=true`（只给答辩演示包）；
- 构建期：`vite.config.ts` 的 `guardMock` 插件在 `mode === 'production'` 且开了 Mock 时**直接抛错**，
  让误发在构建阶段失败，而不是上线后才发现。

### 8.2 切到真实后端

只改环境变量，不改任何页面代码：

```ini
VITE_USE_MOCK=false
VITE_API_BASE_URL=https://your-host/api/v1
VITE_WS_BASE_URL=wss://your-host/ws
```

然后按 `docs/后端开发任务书.md` 逐接口对齐字段。**字段缺失会直接白屏**（模板读 `undefined.title`），
所以后端宁可多给字段，不要少给。

### 8.3 Mock 数据的持久化

大部分 Mock 是内存数组（刷新即回到初始态），但**公告**会写 `localStorage`
（`culinary_ai_mock_notices`，带版本号）。理由：管理员发布了却刷新就没，演示时讲不通。
如果演示前要回到初始态，清掉这个 key 即可。

## 9. 流式问答与文件上传

### 9.1 SSE（`utils/sse.ts`）

用 `fetch + ReadableStream`，**不用 `EventSource`**：需要带 `Authorization` 头与 POST body，
`EventSource` 两者都做不到。

```ts
// 伪代码
const res = await fetch(url, { method: 'POST', headers, body, signal })
const reader = res.body.getReader()
while (true) {
  const { done, value } = await reader.read()
  if (done) break
  buffer += decoder.decode(value, { stream: true })
  // 按 \n\n 切帧，处理 `data: {...}`
}
```

要点：`AbortController` 支持「停止生成」；`decoder.decode(value, { stream: true })` 防止中文被截断。

### 9.2 文件上传

```
选择/拖拽/粘贴 → 本地 objectURL 预览 → POST /files 拿 fileId → 随消息发送 file_ids
```

**坑**：发送时**不能** `URL.revokeObjectURL`（气泡里还要显示缩略图）。用 `takeFiles()`
把所有权移交给消息对象，由消息销毁时释放。

## 10. 导出体系（零依赖）

| 导出 | 实现 | 产物 |
| --- | --- | --- |
| 成绩单 | `utils/export.ts` → `downloadCsv()` | UTF-8 BOM + CRLF + 引号转义，Excel 双击可开 |
| 单人报告 | `views/modules/summary/report.vue`（A4 打印页） | 浏览器打印 → 另存 PDF |

约定：

- 导出范围**必须与角色同源**（学生只有自己一行），在数据层就分流，不能只靠模板 `v-if`。
- 按钮用 `el-button tag="a" target="_blank"`，**不要** `window.open(..., 'noopener')`（返回 null 且被拦时无提示）。
- 学号是文本，CSV 已按字符串输出；不要改成数字列。
- 不引 `xlsx` / `jspdf`：包体多 500KB+，而 CSV + 打印已满足验收。

## 11. 新增一个评价模块的标准动作

以「刀工精细度」为例，8 步：

1. `types/knife.ts`：`KnifeRecord`、`KnifeQuery`、`KnifeResult`；
2. `mock/knife.ts`：演示数据（结构与真实接口一致）；
3. `api/knife.ts`：`analyzeKnife()`、`fetchKnifeRecords()`，Mock 分支写在这里；
4. `views/modules/knife/index.vue`：套 `ModuleShell`，右上 `endpoints` 写清请求/响应；
5. `router/index.ts`：`modules/knife` + `meta.roles`；
6. `router/menu.ts`：加进「评价」组，`titles` 给学生换名（如「我的刀工」）；
7. `config/permissions.ts`：`MODULE_ACCESS` 加一行，必要时加能力点；
8. `docs/后端开发任务书.md` 第 6.5 节表格加一行接口。

> 漏第 7、8 步的后果：页面能进但权限矩阵是错的、后端不知道要写什么接口。

## 12. 构建与部署

### 12.1 前端

```bash
pnpm build          # 产物在 frontend/dist
```

产物结构：`index.html` + `assets/*`（`.js` 已按路由分包，`vue` / `element` 两个 vendor chunk）。

### 12.2 Nginx

```nginx
server {
    listen 443 ssl http2;
    server_name culinary.example.edu.cn;
    root /opt/culinary/dist;

    # SPA history 路由：刷新 /modules/summary 不能 404
    location / { try_files $uri $uri/ /index.html; }

    # 静态资源长缓存（文件名带 hash）
    location /assets/ { expires 30d; add_header Cache-Control "public, immutable"; }

    location /api/ {
        proxy_pass http://127.0.0.1:8000;
        client_max_body_size 25m;
        # SSE 必须关缓冲，否则「打字机」会一次性吐完
        proxy_buffering off;
        proxy_read_timeout 300s;
    }

    location /ws/ {
        proxy_pass http://127.0.0.1:8000;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_read_timeout 300s;
    }
}
```

### 12.3 生产环境清单

- [ ] `VITE_USE_MOCK=false`（否则构建直接失败，这是护栏不是 bug）
- [ ] `VITE_API_BASE_URL` 指到真实网关
- [ ] 开 HTTPS（人脸签到的摄像头 API 在非 `localhost` 下**必须**是安全上下文）
- [ ] 校验 `dist` 里没有 `.map`（`sourcemap: false` 已设）
- [ ] 首屏加载时间在校园网下 ≤ 2s（`element` chunk 约 1MB/gzip 340KB，属于已知成本）

## 14. 排障表（照着查，不要瞎猜）

| 现象 | 最可能的原因 | 怎么确认 / 怎么修 |
| --- | --- | --- |
| 页面白屏，控制台 `Cannot read properties of undefined (reading 'x')` | 接口少返回字段 | Network 看响应体，对照 `types/*.ts` 补字段 |
| 一刷新就回登录页 | token 丢了 / 401 | Application → Local Storage 看 token；看 Network 里 `/auth/profile` 是否 401 |
| `pnpm preview` 后所有数据都是空的 | 生产包 Mock 被强制关闭 | 用 `pnpm dev` 演示；或显式设 `VITE_ALLOW_MOCK_IN_PROD=true` 重新构建 |
| 生产构建报「VITE_USE_MOCK=true 不允许…」 | 保护性报错 | 改 `.env.production` 为 `false` |
| 请求发到 5173 而不是后端 | `VITE_API_BASE_URL` 写成空/错 | 看 Network 的 Request URL；开发走 `/api` 代理即可 |
| 中文返回乱码 | 后端没设 `charset=utf8mb4` / 没返回 `application/json; charset=utf-8` | 看响应头 |
| 时间显示少 8 小时 | 后端返回了 ISO + Z | 统一 `YYYY-MM-DD HH:mm` |
| 上传 413 | Nginx `client_max_body_size` 太小 | 调到 25m 与后端上限对齐 |
| SSE 一次性吐完，没有打字效果 | 反代开了缓冲 / 压缩 | 关 `proxy_buffering`、`gzip off` 对该路径 |
| WS 一分钟断一次 | 反代默认 `proxy_read_timeout 60s` | 调到 300s，前端已有重连退避 |
| 摄像头打不开 | 非安全上下文（http 且非 localhost） | 上 HTTPS 或用 localhost |
| 语音不播 | 浏览器要求用户手势 | 页面上先点一下；看状态栏是否「已开启」 |
| 学生看到全班签到记录 | 隔离写在了模板而不是 store | 查 `faceStore.setScope()` 是否被调用、`loadRecords` 是否强制写 `studentId` |
| 公告发布了但没出现 | 接收对象不含该角色 / 只存了草稿 | 管理端确认状态是「已发布」；接收端 `audience` 过滤 |
| 表格行点了没反应 | 行内用了 `@click` 但没加 `@click.stop` 的按钮冲突 | 给按钮加 `.stop` |
| 类型检查过了但运行报错 | Mock 与真实接口结构不一致 | 对比 `mock/x.ts` 与 `types/x.ts` |

## 15. 已知技术债（接手先知道）

| # | 债务 | 影响 | 建议 |
| --- | --- | --- | --- |
| 1 | `element-plus` 全量引入（1.07MB） | 首屏偏重 | 需要时改成按需（`unplugin-vue-components`），预计降到 300KB |
| 2 | 列表无服务端排序 | 数据量大时排序无意义 | 接 `@sort-change` + 后端 `sortBy/order` |
| 3 | 筛选条件未写入 URL | 刷新丢状态、无法分享 | `router.replace` 同步 query |
| 4 | 无前端错误上报 | 线上白屏只能靠用户投诉 | 接 `window.onerror` + `onErrorCaptured` |
| 5 | Mock 只有内存 + 少量 localStorage | 演示数据不完整 | 保持现状即可，不要为 Mock 造数据库 |
| 6 | 无自动化测试 | 重构靠手点 | 先补 8 条越权用例的 e2e（Playwright）最划算 |
